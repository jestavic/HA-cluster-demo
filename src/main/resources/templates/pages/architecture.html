Nginx — Load Balancer

Acts as the single entry point. Distributes traffic across nodes using round-robin and detects failures via health checks.

  • Round-robin request distribution
  • Auto-removes failed nodes
  • Forwards X-Forwarded-For headers
upstream ha_cluster { server app1:8080; server app2:8080; }
Spring Boot — App Nodes

Multiple stateless instances run in parallel. Any node can handle any request because no local state is stored.

  • Stateless design (Redis for sessions)
  • Unique INSTANCE_ID per container
  • /api/health endpoint exposed
INSTANCE_ID=node-1 SERVER_PORT=8080
Redis — Session Store

Centralised session store. Login on Node 1, next request on Node 2 — Redis keeps you authenticated seamlessly.

  • Spring Session Data Redis
  • Sessions survive node restarts
  • 30-minute TTL expiry
spring.session.store-type=redis spring.session.timeout=30m
PostgreSQL — Database

All nodes share one PostgreSQL instance. Notes created on Node 1 are immediately readable on Node 2.

  • Shared data layer
  • Spring Data JPA + Hibernate
  • HikariCP connection pooling
spring.jpa.hibernate.ddl-auto=update
Failover Flow
  1. 1 Node 1 becomes unavailable (crash or stop).
  2. 2 Nginx detects failure on its next health check.
  3. 3 Nginx marks Node 1 as DOWN and stops routing to it.
  4. 4 All traffic goes to Node 2 automatically.
  5. 5 Session still in Redis — users stay logged in.
  6. 6 Node 1 restarts → health check passes → Nginx re-adds it.
